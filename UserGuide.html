1. What this system does

Every day (once scheduled), your home PC reaches across Tailscale to the office PC, reads the shared folders, and stores an incremental, versioned backup in a restic repository on Disk 1 at home.

About every 14 days, the same script also writes a plain, Explorer-readable full copy of the latest backup onto Disk 2 at home (overwriting the previous Disk 2 copy). That second disk is your safekeeping copy if something goes wrong with Disk 1.

Location A (Office) Location B (Home) ================== ================= Source folders Disk 1: restic repo e.g. D:\Data (versioned / incremental) | ^ | Windows file share | +-------- Tailscale (SMB) ---------------+ | | every 14 days v Disk 2: plain full copy (overwrite / browse in Explorer) The PowerShell script ALWAYS runs on Location B.
Important design choice The job runs on home (B), not office (A). Home owns both backup disks, so after the network pull finishes it can refresh Disk 2 locally without another long network transfer.

What “incremental” means here

  • The first run copies essentially everything (~1.8 TB). That takes a long time.
  • Later runs only send new or changed file content. Unchanged files are not re-uploaded.
  • restic keeps snapshots (points in time), so you can restore yesterday’s version of a file even if it was overwritten or deleted at the office.

2. Purpose, limitations & liability

SyncMe is meant to be a simple way to back up files — shared folders over LAN or Tailscale into a restic repository, with optional Disk 2 plain copy and optional cloud destinations (rclone OAuth for OneDrive / Google Drive).

What SyncMe does

  • File/folder backup into a versioned restic repository (Disk 1).
  • Optional latest-files mirror on Disk 2.
  • HTML console for setup, schedule, restore, and cloud OAuth testing.
  • Email/toast notifications and basic repository integrity checks.

What SyncMe does not do

  • Not bare-metal / full-disk imaging — it will not reinstall Windows or restore an entire system drive. Use a separate imaging tool (e.g. Acronis) for that.
  • Not antivirus or ransomware protection — malware that encrypts source shares or backup disks can still destroy or encrypt data SyncMe can reach. Offline or immutable copies are your responsibility.
  • Not a guarantee of complete backups — locked/unread files (restic exit 3), network drops, disk errors, or cloud throttling can leave gaps.
  • Not a multi-tenant SaaS product — console binds to localhost only; you operate it on your Backup PC.
Ransomware & liability SyncMe cannot stop ransomware. If attackers encrypt your PCs, shares, or backup media, SyncMe and its author are not responsible for resulting loss. 3. Backup results, exit codes & file failures

If a source file cannot be read

restic continues and still creates a snapshot of everything it could read. Unreadable files are skipped. restic returns exit code 3 (incomplete). SyncMe logs this as a WARN, marks the run summary with EXIT3, and (when otherwise successful) still runs prune/archive and updates the last-success stamp. Check the log for which paths were skipped. Prefer Shadow Copies / OfficeAgent for open Office files.

If the backup stops halfway

Snapshots are committed only when the backup step finishes. A killed or crashed run does not leave a half-finished snapshot you can restore. Chunks already stored may remain; the next run deduplicates so unchanged content is not re-uploaded. SyncMe uses a run lock so two backups do not overlap (stale locks clear after ~36 hours by default).

restic exit codes (as SyncMe treats them)

CodeMeaningWhat SyncMe does / warning
0SuccessOK — snapshot complete.
1Fatal errorRun FAILED; prune/archive skipped for that run.
2Go runtime errorRun FAILED.
3Incomplete — some source files unreadWARN / EXIT3 — snapshot often still usable; review skipped paths.
10Repository does not existFAILED — create/init the repo (wizard usually does this).
11Repository already existsUsually only during init; harmless if repo is already set up.
12Wrong passwordFAILED — fix Credential Manager (Operations → Store password).
130Interrupted (Ctrl+C / cancelled)No new snapshot; next run continues with dedupe.

SyncMe process exit is usually 0 on success (including EXIT3 and “already running” lock skip) and 1 on hard failure. Email subjects use STARTED, SUCCESS, FAILED, or CRITICAL (repository integrity check failure).

Each run writes artifacts under Logs\ (often Logs\sets\<setId>\) and Reports\:

Anomalies such as EXIT3, shadow-copy fallback, or stale locks appear as WARN/ERROR text today — not a separate machine event schema. Future log ingestion can parse these files; there is no SIEM exporter yet.

5. What you need before starting

  • Two Windows PCs (office = A, home = B).
  • Both PCs connected to the internet and able to install software.
  • A free Tailscale account (same account/login on both PCs, or same Tailnet).
  • At home: a primary HDD/SSD for the restic repo (Disk 1) with enough free space for the data plus restic overhead (plan for roughly the size of your data, often a bit less over time thanks to deduplication, but leave headroom — e.g. 2.5 TB+ free for 1.8 TB of data is safer).
  • At the Backup PC: space for Disk 1 (restic). Disk 2 (plain copy) is optional.
  • Administrator rights on both PCs (needed for creating users, shares, installing software, and optionally Task Scheduler options).
  • The SyncMe install folder from this project.
  • Time for the first seed backup (can be many hours or days depending on office upload speed).
Password safety You will choose a strong restic repository password. If you lose it, you cannot restore from Disk 1. Store it in a password manager. Do not put it in Config.ps1.

Shadow Copies for open Office files

Location A — Office then consumed from home

VSS cannot be created across SMB from home. Enable Shadow Copies for Shared Folders on the office data volume, then run the OfficeAgent scripts so a pointer file tells home which @GMT-… path to back up.

  1. On office: drive Properties → Configure Shadow Copies → Enable for the data volume.
  2. On office (elevated): OfficeAgent\Enable-SyncMeShadowCopies.ps1 — see OfficeAgent\README.md.
  3. Confirm .monarch-latest-shadow.txt appears in the share root (readable from home).
  4. Home config: UseShadowCopySources = $true (wizard asks this). Schedule home backup after the office pointer task (default 00:30).
restic exit code 3 Means some files were unread (often open .xlsx/.docx/.pst on a live share). Snapshot may still exist. Reports show Open-file risk and Source mode. Prefer ShadowCopy mode over LiveFallback. Full exit-code table: Backup results, exit codes & file failures.

Repository integrity checks

Location B — Home

  • Daily: restic check (structural — indexes/snapshots).
  • Weekly (Sunday by default): restic check --read-data-subset=n/7 rotating by weekday so pack data is verified over a week.
  • Failures set repo status to CHECK_FAILED / CORRUPTED, fail the run, and email with CRITICAL when applicable.
  • Switches: -SkipCheck, -RunDataCheck, -CheckOnly (menu uses these).

4. Step 1 — Install and connect Tailscale

Both PCs

1.1 Install Tailscale

  1. On the office PC and the home PC, open a browser and go to https://tailscale.com/download/windows.
  2. Download and run the Windows installer.
  3. Sign in with the same Tailscale account / organization on both machines so they can see each other.
  4. Leave Tailscale running (system tray icon).

1.2 Turn on MagicDNS (recommended)

  1. In a browser, open the Tailscale admin console: https://login.tailscale.com/admin/dns.
  2. Ensure MagicDNS is enabled.
  3. Optionally rename machines to clear names like office-pc and home-pc under Machines.

1.3 Verify connectivity

On the home PC, open PowerShell and run (replace with your office name):

tailscale status
Test-Connection office-pc -Count 2

You should see the office machine listed and ping replies (or at least a successful route). If this fails, fix Tailscale before continuing — the backup cannot work without it.

Firewall note Tailscale usually handles connectivity without opening router ports. If ping fails, check that Tailscale is logged in on both sides and that neither machine is stuck offline or needing an ACL approval in the admin console.

5. Step 2 — Prepare Location A (office): user + folder share

Location A — Office

2.1 Create a dedicated backup user

Using a dedicated account is safer than sharing your personal login.

  1. Press Win + R, type lusrmgr.msc, press Enter. (On Windows Home, lusrmgr may be missing — use Settings → Accounts → Other users → Add account, or run the PowerShell below.)
  2. Create a local user, for example BackupUser.
  3. Set a strong password. Save it in your password manager.
  4. You do not need this user to be an Administrator for a read-only backup.

PowerShell alternative (run as Administrator on the office PC):

$password = Read-Host -AsSecureString "Password for BackupUser"
New-LocalUser -Name "BackupUser" -Password $password -FullName "Backup User" -Description "Read-only backup over Tailscale"
# Optional: ensure the account is not expired / disabled
Enable-LocalUser -Name "BackupUser"

2.2 Decide which folders to back up

Example: everything under D:\Data. You can share one parent folder or several folders (each becomes its own share, or one parent share covering all).

Tip for the first test Create a tiny folder such as D:\BackupTest with a few documents. Share that first and run a smoke test (Step 11) before pointing at the full 1.8 TB.

2.3 Share the folder

  1. In File Explorer, right-click the folder (e.g. D:\Data) → Properties → Sharing tab.
  2. Click Advanced Sharing…
  3. Check Share this folder.
  4. Share name: e.g. Data (this becomes \\office-pc\Data).
  5. Click Permissions.
    • Remove broad groups if you want tighter control (optional).
    • Add BackupUser.
    • Give BackupUser Read only (sufficient for backup).
    • Apply / OK.
  6. Also check the Security (NTFS) tab: BackupUser needs at least Read & execute, List folder contents, and Read on the folder and files. If inheritance does not grant it, Add the user and allow those rights.

PowerShell alternative (Administrator on office PC):

$folder = "D:\Data"
$shareName = "Data"
New-SmbShare -Name $shareName -Path $folder -ReadAccess "BackupUser"
# Ensure NTFS read for BackupUser on the folder tree
icacls $folder /grant "BackupUser:(OI)(CI)R" /T

2.4 Allow file sharing through the firewall (if needed)

  1. Windows Security → Firewall → Allow an app through firewall.
  2. Ensure File and Printer Sharing is allowed on the relevant profiles. Tailscale often uses a profile that already permits this between Tailscale IPs; if home cannot connect later, revisit this.

2.5 Note the exact UNC path

From home you will use:

\\office-pc\Data

If Tailscale shows a different hostname, use that name instead of office-pc.

6. Step 3 — Prepare Location B (home): disks + folders

Location B — Home

3.1 Identify Disk 1 and (optional) Disk 2

  • Disk 1 — holds the restic repository (versioned backup) on this Backup PC. Use any drive letter that exists on your machine.
  • Disk 2 — optional plain full copy. Leave blank in the SyncMe wizard for restic-only.

Examples in this guide use D: / E: for illustration only — configs ship empty so SyncMe is portable across servers.

3.2 Create the destination folders

Open PowerShell on the Backup PC (adjust letters to match your disks):

New-Item -ItemType Directory -Path "D:\Backups\repo" -Force
# Optional Disk 2:
# New-Item -ItemType Directory -Path "E:\Archive\Latest" -Force
Do not store other important files inside these folders The archive step can delete everything under Disk 2 when it is configured (ClearArchiveBeforeRestore = $true). Keep only the backup mirror there.

3.3 Confirm free space

Get-PSDrive | Where-Object { $_.Provider.Name -eq 'FileSystem' } | Format-Table Name, Used, Free

Disk 1 needs substantial free space for the restic repo. If you use Disk 2, its free space should exceed your total source data size.

7. Step 4 — Install restic on Location B

Location B — Home

4.1 Download restic

  1. Open https://github.com/restic/restic/releases/latest.
  2. Download the Windows AMD64 zip, e.g. restic_X.Y.Z_windows_amd64.zip.
  3. Extract restic.exe.

4.2 Place it on your PATH (recommended)

  1. Create a folder such as C:\Tools\restic\.
  2. Move restic.exe into that folder.
  3. Add that folder to the system or user PATH:
    • Settings → System → About → Advanced system settings → Environment Variables.
    • Under User or System variables, edit Path → New → C:\Tools\restic → OK.
  4. Close and reopen PowerShell so PATH updates.

Verify:

restic version

You should see a version number. If the command is not found, either fix PATH or set the full path later in Config.ps1:

ResticPath = 'C:\Tools\restic\restic.exe'

4.3 Alternative: install via winget (if available)

winget search restic
# Install using the Id shown in the search results, for example:
# winget install --id Restoric.Restic -e
# (Ids can change — always confirm from search output.)

After install, open a new PowerShell window and run restic version. If winget has no package, use the GitHub zip method in 4.1–4.2.

9. Step 6 — Verify you can open the office share from home

Location B — Home

This step must succeed before restic will work.

  1. On the home PC, open File Explorer.
  2. In the address bar type: \\office-pc\Data (use your real names) and press Enter.
  3. When prompted, sign in as office-pc\BackupUser (or OFFICE-PC\BackupUser) with the password you created. Check Remember my credentials if offered.
  4. Confirm you can browse files.

PowerShell checks:

Test-Path "\\office-pc\Data"
Get-ChildItem "\\office-pc\Data" | Select-Object -First 10
If this fails, stop here Fix share permissions, Tailscale connectivity, firewall, or credentials first. The backup script will fail at preflight if the source is unreachable.

Common connection fixes

  • Use the Tailscale IP temporarily: \\100.x.x.x\Data — if that works but the name does not, MagicDNS/name is the issue.
  • On office PC: confirm the share exists — Get-SmbShare.
  • On office PC: confirm BackupUser can log on locally / is not locked out.
  • Try: net use \\office-pc\Data /user:office-pc\BackupUser * and enter the password when prompted.

10. Step 7 — Store passwords in Windows Credential Manager

Location B — Home

SyncMe reads secrets from Windows Credential Manager. Never put the restic password in Config.ps1. Prefer the SyncMe UI — you usually do not need cmdkey.

7.1 Choose a strong restic password

Use a long random password (password manager generated). This password encrypts the entire restic repository. Losing it means losing access to Disk 1 backups.

7.2 Store the restic password

Recommended: In SyncMe, use the setup wizard Passwords step, or Operations → Store password (same password used when the repo was created).

Advanced / manual fallback (Command Prompt):

cmdkey /generic:SyncMeRestic /user:restic /pass:PASTE_YOUR_STRONG_PASSWORD_HERE
Command history tip Putting a password on the command line may leave it in history. Prefer Operations → Store password. If you use cmdkey, the target must be exactly SyncMeRestic (or SyncMeRestic-<setId> for extra sets) unless you change ResticCredentialName in config. User can be restic; password is your repo password.

Verify the entry exists:

cmdkey /list

You should see a target named SyncMeRestic.

7.3 Optional — store SMB share credentials

Prefer the SyncMe wizard Passwords step (share credentials checkbox). If File Explorer remembered the share login and the same Windows user will run the scheduled task, you may leave ShareCredentialName = '' in config (default).

Advanced fallback if the scheduled task cannot access \\office-pc\Data automatically:

cmdkey /generic:SyncMeShare /user:office-pc\BackupUser /pass:BACKUPUSER_PASSWORD_HERE

Then in Config.ps1 set:

ShareCredentialName = 'SyncMeShare'

Optional: set ShareDriveLetter = 'Z' if you prefer mapping a drive letter during the run; leave empty to connect without a drive letter.

7.4 Store SMTP credentials (manual path)

Prefer SyncMe.bat which collects SMTP in the wizard. Advanced fallback:

cmdkey /generic:SyncMeSmtp /user:smtp_login@example.com /pass:YOUR_SMTP_OR_APP_PASSWORD

Then set the email fields in Config.ps1 (see Email notifications).

11. Step 8 — Initialize the restic repository (once only)

Location B — Home

This creates an empty encrypted repository on Disk 1. Do this once.

# Use the SAME password you stored in Credential Manager
$env:RESTIC_PASSWORD = "PASTE_YOUR_STRONG_PASSWORD_HERE"
restic init --repo "D:\Backup\restic-repo"
Remove-Item Env:RESTIC_PASSWORD

Expected success message looks like: created restic repository … at D:\Backup\restic-repo

Do not run init again on a repo that already has data Re-initializing into a non-empty repo is wrong. If init says the directory is not empty / already a repository, stop and use the existing repo.

Quick check:

$env:RESTIC_PASSWORD = "PASTE_YOUR_STRONG_PASSWORD_HERE"
restic -r "D:\Backup\restic-repo" snapshots
Remove-Item Env:RESTIC_PASSWORD

An empty new repo will show no snapshots yet — that is fine.

14. Step 11 — Smoke test with a small folder

Location B — Home

Do not start with 1.8 TB Prove the whole path works with a few megabytes first.
  1. On the office PC, ensure D:\BackupTest (or similar) is shared and has a few sample files.
  2. On home, set Config.ps1 SourcePaths to that test share.
  3. Open PowerShell:
cd C:\SyncMe
.\SyncMe-Backup.ps1 -SkipArchive

-SkipArchive skips the Disk 2 restore for this test so it finishes faster.

What success looks like

  • A “backup started” notification.
  • Console log lines ending with a Finished summary.
  • A “backup completed” notification.
  • New files under Logs\:
    • backup-YYYYMMDD-HHmmss.log
    • restic-YYYYMMDD-HHmmss.jsonl
  • New HTML report under Reports\backup-YYYYMMDD-HHmmss.html — open it in your browser.
  • Exit code 0 (no red fatal errors).

Confirm a snapshot exists:

$env:RESTIC_PASSWORD = "YOUR_PASSWORD"
restic -r "D:\Backup\restic-repo" snapshots
Remove-Item Env:RESTIC_PASSWORD

If the smoke test fails

  1. Open the newest file in Logs\ and read the ERROR lines.
  2. Open the HTML report Errors section.
  3. Jump to Troubleshooting.

15. Step 12 — First full backup (~1.8 TB)

Both PCs must stay online

  1. Edit Config.ps1 and set SourcePaths to your real office data share(s).
  2. On both PCs, disable sleep for the duration (see Step 15).
  3. Start the backup on home:
cd C:\SyncMe
.\SyncMe-Backup.ps1 -SkipArchive

Still skip archive on the first seed if you prefer; you can run -ForceArchive afterward once Disk 1 has a complete snapshot (Step 13). Archiving restores the full tree to Disk 2 and also takes a long time / lots of disk I/O.

Expect a long first run Duration depends mainly on the office upload speed through your ISP and Tailscale. Overnight or multi-day runs are normal for ~1.8 TB. Later daily runs should be much smaller.

While it runs

  • Do not turn off either PC.
  • You can watch the log file in Logs\ growing.
  • If the network drops, fix connectivity and run the script again — restic will continue efficiently; already stored content is not re-sent from scratch.

When it finishes

  • Open the HTML report and confirm status SUCCESS (or review warnings).
  • Note: restic exit code 3 means some files could not be read (often locked Office files). The snapshot may still be usable; check the log for which files failed.

16. Step 13 — Force the Disk 2 archive once

Location B — Home

After you have at least one good snapshot on Disk 1, create the first plain full copy on Disk 2: 

cd C:\SyncMe
.\SyncMe-Backup.ps1 -ForceArchive

This will:

  1. Run a normal backup + prune (same as daily).
  2. Clear E:\Archive\OfficeMirror (if ClearArchiveBeforeRestore is true).
  3. Run restic restore latest into that folder.
  4. Write a timestamp to Logs\last-archive-utc.txt so the next automatic archive waits ~14 days.
About folder nesting Because sources are UNC paths, the restored tree under Disk 2 may include path segments reflecting the original share path (not only a flat copy of file names at the root of OfficeMirror). That is expected. Browse until you find your files; they are all under ArchivePath.

Browse Disk 2 in Explorer to confirm files are present and readable without restic.

17. Step 14 — Schedule the automatic run

In the Setup wizard Schedule step, choose a start date, time, and recurrence (Once, Daily, or Weekly with days of week). Optionally set an end date. SyncMe registers a Windows Scheduled Task for the set. After Apply, use Run dry run to verify the backup before relying on the schedule.

Location B — Home

14.1 Register with the helper script

cd C:\SyncMe
.\Register-BackupTask.ps1 -Time '01:00'

This creates a scheduled task named SyncMe-Backup that runs daily at 01:00 as your user, interactively (so toast notifications can appear while you are logged on).

14.2 Verify the task

  1. Press Win + R, type taskschd.msc, Enter.
  2. Find SyncMe-Backup in the Task Scheduler Library.
  3. Confirm Trigger (daily time) and Action (powershell.exe with -File …SyncMe-Backup.ps1).
  4. Optional: right-click → Run to test once.

14.3 Run whether user is logged on or not (optional)

  1. Open the task → General tab.
  2. Select Run whether user is logged on or not.
  3. Enter your Windows account password when prompted.
  4. Understand that toast popups may not show in this mode; rely on Reports\ and Logs\.
  5. Ensure that account can still read \\office-pc\Data (you may need the optional OfficeBackupShare credential from Step 7.3).

14.4 Manual registration (alternative)

$script = 'C:\SyncMe\SyncMe-Backup.ps1'
$action = New-ScheduledTaskAction -Execute 'powershell.exe' `
  -Argument "-NoProfile -ExecutionPolicy Bypass -File `"$script`""
$trigger = New-ScheduledTaskTrigger -Daily -At 01:00
Register-ScheduledTask -TaskName 'SyncMe-Backup' -Action $action -Trigger $trigger -Force

14.5 Unregister

.\Register-BackupTask.ps1 -Unregister
Biweekly Disk 2 archive needs no second task The daily script checks Logs\last-archive-utc.txt. When 14 or more days have passed (configurable), it automatically restores to Disk 2 during that night’s run.

18. Step 15 — Keep both PCs awake for the backup window

Both PCs

If either PC sleeps, the backup will fail or stall.

Quick settings (GUI)

  1. Settings → System → Power & sleep.
  2. Set Sleep to Never while plugged in (at least during the backup window / first seed).
  3. On laptops, keep AC power connected.

PowerShell examples (plugged in)

# Show current scheme
powercfg /getactivescheme

# Example: never sleep on AC (0 = never). Adjust as you prefer after the seed completes.
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /change monitor-timeout-ac 30

Office PC considerations

  • Must be powered on and Tailscale connected when home starts the job.
  • Disks containing source data must be mounted (if you use external drives at the office, they must be plugged in).

19. Day-to-day use

  • Let the scheduled task run daily. You should get start/finish toasts (if logged on and toasts enabled) and/or emails (if SMTP is configured).
  • If the task runs while you are logged off, rely on email and Reports\ rather than toasts.
  • Open Reports\ occasionally (or the HTML attachment on complete emails): data added, snapshot id, whether archive ran, any errors.
  • About every two weeks, Disk 2 refreshes automatically. Confirm occasionally that E:\Archive\OfficeMirror still looks populated.
  • After major office folder moves/renames, check one report to ensure sources still resolve.

Manual run anytime

cd C:\SyncMe
.\SyncMe-Backup.ps1

20. How to restore files

Backup PC

Option A — SyncMe GUI (recommended)

  1. Open SyncMe → Operations.
  2. Click Refresh snapshots.
  3. Choose Restore latest or select a row and Restore selected.
  4. Pick a target folder outside the restic repo (use Suggest for E:\SyncMe-Restore\…).
  5. Or click Open Disk 2 archive for the latest plain copy.

Option B — Latest plain copy from Disk 2 (Explorer)

  1. Open E:\Archive\OfficeMirror in Explorer (or use the GUI button).
  2. Copy the files you need to wherever you want them.
  3. Remember: Disk 2 is only as fresh as the last biweekly (or forced) archive.

Option C — Any snapshot from Disk 1 (restic CLI)

$env:RESTIC_PASSWORD = "YOUR_PASSWORD"
restic -r "D:\Backup\restic-repo" snapshots

# Restore an entire snapshot into a temporary folder
restic -r "D:\Backup\restic-repo" restore SNAPSHOT_ID --target "E:\SyncMe-Restore\temp"

# Restore only a specific path (example — adjust to your stored paths)
restic -r "D:\Backup\restic-repo" restore SNAPSHOT_ID --target "E:\SyncMe-Restore\temp" --include "/path/inside/snapshot"

Remove-Item Env:RESTIC_PASSWORD

Use latest instead of a snapshot ID to restore the most recent snapshot. Never restore into the live restic repository folder.

Option D — Mount a snapshot (advanced)

From SyncMe Operations, use Mount repo / Unmount. If WinFsp is missing, click Install WinFsp (Windows may ask for permission). If the repository password is missing, click Store password. Mounts appear under Logs\mount\<setId> by default. Mount is for browsing; use Operations restore for a permanent copy.

23. Troubleshooting

SymptomWhat to check / do
Repository password not stored / Credential Manager target not found In SyncMe: Operations → Store password (or Edit set → Passwords). Advanced: cmdkey /list and recreate SyncMeRestic / SyncMeSmtp. Names must match config.
No email / SMTP auth failed Confirm server/port/SSL; use an app password for Gmail; enable Authenticated SMTP for M365; recreate SyncMeSmtp via the wizard; check log WARN lines.
Complete email missing HTML attachment Report must exist under Reports\. If report generation failed, email still sends without attachment — check log.
Emails go to spam Whitelist the From address; prefer sending from a real mailbox you control (not a forged From).
Cannot reach source host / Test-Connection fails Both Tailscale clients logged in? tailscale status on both PCs. Correct SourceHost name?
Test-Path \\office-pc\Data is False Share missing/permissions; wrong share name; SMB credentials; try net use; check office firewall.
restic not found Install restic; restart PowerShell; or set full ResticPath in config.
Repository path does not exist Create D:\Backup\restic-repo and run restic init (Steps 3 and 8).
Wrong password / repository cannot be opened Password in Credential Manager must match the password used at restic init. Use Operations → Store password to update it.
Mount needs WinFsp / mount fails On Operations click Install WinFsp and approve the Windows security prompt. Then Mount repo again.
Exit code 3 from restic backup Some source files unread (often locked Office). Snapshot may still be OK. See exit codes; prefer Shadow Copies.
Exit code 1 / 2 / 12 / other non-3 Backup failed — open the newest Logs\ ERROR lines. Code 12 = wrong restic password. Code 10 = repo missing.
Backup cancelled / killed mid-run No new snapshot. Re-run; restic dedupes already stored chunks. See interrupted backups.
Script blocked by execution policy Set-ExecutionPolicy -Scope CurrentUser RemoteSigned or run via the scheduled task which uses Bypass.
No toast notifications Install BurntToast; ensure you are logged on; task may be set to run whether logged on or not; try -NoNotify off; check Focus Assist.
Disk 2 empty / unexpected nesting Run with -ForceArchive; wait for restore to finish; browse subfolders under ArchivePath for UNC-style nesting.
Archive deleted files I left on Disk 2 Expected when ClearArchiveBeforeRestore = $true. Do not store unique data only in the archive folder.
First backup extremely slow Normal for multi-TB seed. Check office upload speed; keep both PCs awake; subsequent runs are incremental.
Scheduled task runs but cannot see the share Configure ShareCredentialName / OfficeBackupShare; or run task as the same user that can open the UNC path interactively.
Want to see what would happen without writing Run .\SyncMe-Backup.ps1 -WhatIf (still may need credentials/config valid for preflight).

Where to look first when something fails

  1. Logs\backup-*.log — human-readable transcript.
  2. Reports\backup-*.html — summary + errors.
  3. Logs\restic-*.jsonl — raw restic JSON lines.
  4. Task Scheduler → task History tab (if enabled) for scheduled runs.

24. Final checklist

You are done when Daily reports (and emails) show successful incremental backups, snapshots list grows then prunes sanely, and Disk 2 refreshes about every two weeks with browseable files.
