User Guide

SyncMe is a simple file-level backup console for Windows. Install it on a Backup PC, pull UNC shares over LAN and/or Tailscale, and store versioned snapshots with restic (local disk, NAS, or cloud via rclone / OneDrive).

Overview

SyncMe runs only on the Backup PC. Source PCs only need shared folders (plus Tailscale when offsite). You create one or more backup sets — each with its own sources, schedule, and restic repository destination.

Source PCs (UNC shares) | LAN and/or Tailscale SMB v Backup PC — SyncMe console + Task Scheduler | +-- Backup set A --> restic repo (local / NAS / rclone) +-- Backup set B --> restic repo (local / NAS / rclone) +-- ...
  • Version history comes from restic snapshots (not a second plain-disk mirror).
  • LAN-only is fine; Tailscale is optional for offsite sources.
  • Cloud destinations use rclone as restic’s backend (OAuth from the console).

What you need before starting

  • One Windows Backup PC (Windows 10/11 or Windows Server) where SyncMe is installed.
  • One or more source PCs with folders shared so this PC can open them as UNC (e.g. \\pc-name\Data or \\pc-name\C$\Users\…).
  • Network path: LAN, Tailscale, or both — Tailscale only if sources are offsite.
  • Space for each set’s restic repository (local disk, NAS UNC, or cloud via rclone). Leave headroom beyond the size of your data.
  • restic (the wizard can install it). rclone if you use OneDrive/Google Drive.
  • Administrator rights as needed for shares, Task Scheduler, and optional Shadow Copies on sources.
  • A password manager for the restic repository password (and SMTP/share secrets if used).
  • Time for the first seed backup (hours or longer depending on data size and network speed).
Password safety The restic password encrypts the repository. If you lose it, you cannot restore or recover. Save it in a password manager or other safe place when you create it — Credential Manager on the Backup PC is not enough if that machine dies. Do not put passwords in Config.ps1.

Limitations & liability

SyncMe is meant to be a simple way to back up files — UNC sources into restic, with optional cloud via rclone OAuth. Use Add backup set for each PC or schedule.

What SyncMe does

  • File/folder backup into versioned restic repositories (one per set).
  • HTML console for setup, schedule, restore, and cloud OAuth.
  • Email/toast notifications and repository integrity checks.

What SyncMe does not do

  • Not bare-metal / full-disk imaging — use a separate imaging tool for whole-system restore.
  • Not antivirus or ransomware protection — encrypted or wiped disks/shares are still possible.
  • You must verify backups and restores — locked files (exit 3), network drops, excludes, or cloud throttling can leave gaps. Use dry run, Reports/Logs, Operations Check, and a test restore to an empty folder against your sources.
  • Not a multi-tenant SaaS — console binds to localhost on the Backup PC.
Restic password The restic password encrypts the repository. Without it there is no restore or recovery. Save it in a password manager or other safe place when you create it. Credential Manager keeps this Backup PC able to run jobs; your vault copy is for disaster recovery if the PC dies. Do not put the password in Config.ps1.

Exit codes & file failures

If a source file cannot be read

restic still creates a snapshot of everything it could read. Unreadable files are skipped. restic returns exit code 3. SyncMe logs a WARN, tags the summary with EXIT3, and (when otherwise successful) continues prune and updates last-success. Prefer Shadow Copies / OfficeAgent for open Office files.

If the backup stops halfway

No half-finished snapshot is committed. The next run is a fresh backup; restic dedupes already-stored chunks. SyncMe uses a run lock so two backups do not overlap.

CodeMeaningSyncMe behavior
0SuccessOK
1Fatal errorFAILED
2Go runtime errorFAILED
3Some source files unreadWARN / EXIT3 — snapshot often usable
10Repo does not existFAILED — init via wizard
11Repo already existsUsually only during init
12Wrong passwordFAILED — Credential Manager
130InterruptedNo new snapshot; retry later

Email subjects use STARTED, SUCCESS, FAILED, or CRITICAL (repo check failure).

Setup wizard

Backup PC Double-click SyncMe.bat (optionally open this guide when prompted).

Browser opens http://127.0.0.1:17845/. Complete the wizard once:

  1. Confirm this is the Backup PC; name the backup set.
  2. Prerequisites — install restic (and rclone if needed).
  3. Network mode + source UNC folders.
  4. Destination — local folder, NAS UNC, or cloud (rclone OAuth).
  5. Passwords (Credential Manager), optional email, schedule.
  6. Apply — Task Scheduler registers the job.
Recommended path Use the wizard and dashboard. You do not need to edit Config.ps1 by hand for a normal install.

Backup sets

Use Add backup set for another source PC, user, or schedule. Each set has its own restic repository path, task, and last-success stamp. The SyncMe-Watchdog task watches all sets for overdue runs.

Stagger run times when several sets share the same Backup PC or uplink.

Shadow copies (open Office files)

VSS cannot be created across SMB from the Backup PC. On the source PC, enable Shadow Copies for Shared Folders, then run OfficeAgent\Enable-SyncMeShadowCopies.ps1 (elevated). See OfficeAgent\README.md.

restic exit code 3 Often open .xlsx/.docx/.pst on a live share. Prefer ShadowCopy mode. See exit codes.

Email notifications

Optional SMTP from the wizard. Subjects include STARTED, SUCCESS, FAILED, or CRITICAL. Complete emails can attach the HTML report. Passwords stay in Credential Manager (SyncMeSmtp). SyncMe enables TLS 1.2 and validates the SMTP certificate (no bypass). Mail failures are logged as warnings and do not fail the backup job.

Repository integrity checks

  • Structural restic check (configurable).
  • Weekly data subset check rotating by weekday.
  • Failures can mark the run CRITICAL and fail the job.

Tailscale (optional)

Only needed when the Backup PC cannot reach source shares on the LAN.

  1. Install Tailscale on source and Backup PC; same account / tailnet.
  2. Confirm tailscale status and that UNC paths work (e.g. \\source-pc\Data).
  3. In SyncMe, set network mode to Tailscale or Both.

Day to day

  • SyncMe.bat or SyncMe-Menu.bat — dashboard / operations.
  • Scheduled jobs run without leaving the console open.
  • Switch sets on the dashboard; Run now / dry run / prune from Operations.
  • Keep both ends awake for the backup window on large first seeds.

Restore

  1. Operations → refresh snapshots.
  2. Select a snapshot → Browse selected to open folders inside that snapshot (roots such as C:\Pastel19). Double-click folders; Use this path fills the optional include field (one file or folder). Leave include blank for a full restore.
  3. Restore latest or selected snapshot to an empty folder outside the live restic repo (never into the source share). Use Suggest for a safe target.
  4. Optional: Operations → More… → Export Rescue Kit for a printable recovery sheet (repo path + Credential Manager target — password stays in your vault).
Retention & integrity (1.3.0+) Dashboard → Retention & integrity: keep policies, optional Append-Only Mode (skips prune / blocks snapshot delete), and optional pre/post backup script paths (must be non-interactive for Task Scheduler). Weekly data checks run an advisory restore drill (`restic dump` of up to three random files). Results show as PASS / FAIL / SKIP in the HTML report and do not fail the overall job. Structural check and data-subset failures still fail the run.
Windows note Official restic builds on Windows do not include mount. SyncMe’s browse panel lists paths via restic ls; restore still copies files out with restic restore. UNC-era snapshots (paths starting with \\) cannot be browsed or restored on Windows — run a new backup after SyncMe’s drive-letter rewrite, then restore that snapshot.
Verify against the source Spot-check restored files (names, sizes, dates) against the live share for critical paths. After backups: read Reports/Logs (exit 3 = unread files), run Operations Check, and periodically test-restore. You need the restic password — keep a vault copy, not only Credential Manager. Later runs may show tiny “Data added” while “Total bytes processed” stays large — that is normal deduplication.
