SyncMe

HTML console for restic-powered file backup · v1.3.0

A simple frontend for restic, rclone, and Task Scheduler — pull LAN or Tailscale shares to a Backup PC. Browse snapshots, export a Rescue Kit, and harden repos with append-only policy and restore drills.

User Guide FAQ GitHub

What it is

File-level backup managed from a browser — not a cloud SaaS product.

SyncMe runs only on the Backup PC (Windows 10/11 or Windows Server). Source machines only need shared folders — and Tailscale when they are offsite.

Open the HTML5 console on localhost, configure backup sets, schedule them in Windows Task Scheduler, and let restic create encrypted, deduplicated, versioned snapshots. Optional cloud destinations use rclone as restic’s backend (OneDrive / Google Drive OAuth).

No PHP. No database. No agent installed on every source PC.

Built on trusted tools

SyncMe is an orchestration frontend — PowerShell host + HTML console — not a replacement for restic or rclone.

Backup engine

restic

Encrypted, deduplicated, versioned snapshots — prune, check, and restore.

Cloud backend

rclone

Used only as restic’s cloud remote (e.g. OneDrive). Not folder Sync/Bisync in this release.

Open files on source

OfficeAgent

Optional VSS helper on the source PC so locked Office/database files can be read during backup.

Optional VPN

Tailscale

Reach offsite SMB shares so the Backup PC can pull sources over the internet.

Host: PowerShell 5.1 HttpListener on 127.0.0.1:17845 · UI: HTML5 + vanilla JS · Schedule: Windows Task Scheduler · Secrets: Credential Manager · See THIRD-PARTY-NOTICES.txt in the package.

Features

Expand a topic to read more — same collapsible style as the console.

Multiple backup sets with a switcher on the dashboard. Each set can include several UNC folders. Network mode: LAN, Tailscale, or both. Wake-on-LAN optional per set.

restic repository (required per backup set): local disk, NAS UNC, or rclone cloud (OneDrive / Google Drive). Bandwidth limits and retries for cloud uploads. Use Add backup set for another source PC or schedule.

Once, daily, or weekly schedules via Windows Task Scheduler. Live restic JSON progress in the console, cancel with a warning, and detached “Run now” so a manual backup survives closing SyncMe.

Editable keep policies and prune from the console. Optional Append-Only Mode skips prune and blocks snapshot deletion. Structural integrity check, weekly data subset, and an automated restore drill (random file) during data checks. Pre/post backup script hooks (non-interactive) for stopping/starting services around the run. Restore latest or selected snapshots — with folder browse — from Operations into an empty test folder.

Export Rescue Kit from Operations writes a printable HTML sheet with repo paths, Credential Manager target names, and manual restic recovery steps — never the restic password. Keep the password in your offline vault; use the kit when rebuilding a Backup PC. Stale restic locks from crashed runs can be unlocked automatically when no other SyncMe/restic process is alive.

Optional OfficeAgent scripts on the source PC use Volume Shadow Copy so open Office documents can be backed up cleanly instead of failing with locked-file warnings.

Limitations

Honest boundaries so you know what SyncMe is — and is not.

SyncMe is file-level backup only. It does not image whole disks, scan for malware, or stop ransomware. Verify backups and keep separate recovery copies.

The HTML console binds to 127.0.0.1 on the Backup PC. It is not a multi-tenant SaaS and is not meant to be exposed to the internet. Use RDP when managing a Server.

This release uses rclone only so restic can store a repository in the cloud. Folder Sync/Bisync mirroring is planned later. Consumer clouds may throttle large uploads — prefer a local disk or NAS for the primary restic repository when possible.

The restic password encrypts the repository. Without it there is no restore and no recovery. When the wizard creates it, save a copy in a password manager or other safe place — not in Config.ps1 and not only on the Backup PC. Windows Credential Manager keeps the machine able to run backups; your vault copy is for disaster recovery if that PC dies. Use Operations → Export Rescue Kit for printable recovery instructions (password stays out of the file).

Locked files, network drops, excludes, and cloud throttling can leave gaps — you verify what landed. After Apply: Run dry run, then a real backup. Read Reports and Logs (restic exit 3 lists unread files). Use Operations Check for repository health. Restore a sample into an empty test folder and spot-check names, sizes, and dates next to the live share. Restore into an empty test folder (never the live repo or live source) and compare critical paths to the source.
